# 灵感 AI · 中文在线工具平台

基于当前 `tz3558336-gif/codex-project` 个人网站原地升级，使用原生 HTML、CSS、JavaScript，无构建步骤，兼容 GitHub Pages 项目子路径。原有文件保留并更新。

## 能力与边界

| 工具 | 当前实现 |
| --- | --- |
| AI 文章生成器 | 主题、读者、风格、字数与要求表单；本地整理提示词、复制、导出接口请求 JSON。**尚未接入 API，不生成文章。** |
| 电商标题生成器 | 商品信息、卖点、平台、数量与长度表单；本地整理提示词、复制、导出请求 JSON。**尚未接入 API，不生成标题。** |
| 商品利润计算器 | 真实计算平台费用、利润、销售利润率、总成本与保本售价，支持 CSV 导出 |
| 批量商品利润分析器 | 多行商品实时计算、总利润、亏损标记、最高利润商品、草稿自动保存、CSV 导出 |
| 商品利润分析历史记录 | 保存有效批量分析快照、查看详情、恢复到草稿、单条删除及清空；日期、商品数量、总利润与明细本地保存 |
| 批量文本处理 | 行首尾去空格、字面替换、大小写、移除空行、逐行去重、添加行号、字符/行数统计、复制和 TXT 下载 |
| AI 提示词管理 | 新增、编辑、删除、搜索、分类筛选、复制、JSON 导入/导出、重复条目跳过与本地持久化 |
| 用户中心 | 本地显示名称与工作方向、真实提示词/收藏数量、收藏入口、确认后清除平台本地数据 |

工具广场提供搜索、分类和工具收藏。页面使用 hash 路由，刷新子页面不需要服务器重写规则。没有账号认证、云同步、会员、支付、模拟余额或虚构 AI 结果。

### 利润计算规则

- 平台费用 = 售价 × 费率 / 100。
- 单件利润 = 售价 − 商品成本 − 运费 − 平台费用。
- 销售利润率 = 利润 ÷ 售价 × 100%，不是成本收益率。
- 保本售价 =（商品成本 + 运费）÷（1 − 费率 / 100）。
- 费率 100% 且成本/运费有正值时无法保本；成本和运费均为 0 时任意正售价均保本。
- 售价必须大于 0，其他金额非负，金额上限 10 亿元，费率 0–100%。金额精确到分，计算保留中间精度，结果显示两位小数。
- 这里只核算单件商品，不含广告、税费、退货等未输入支出。

### 批量商品利润分析器

从工具广场或左侧导航进入「批量商品利润分析器」（`#batch-profit`），点击「添加商品」录入商品名称、成本、售价、运费与平台费率。每次输入即重新计算单件利润、利润率、平台费用和保本售价，无需登录、API、数据库或服务器。

- 最多 200 行，支持逐行删除；「清空分析数据」经确认后仅清除批量分析数据，不影响提示词、收藏和个人资料。
- 总利润为**每种有效商品各销售一件的单件利润之和**，不是含销量的经营总利润。空白或非法行明确标为待完善，不计入总利润、亏损数量或最高利润商品；汇总显示有效行数。
- 自动标记亏损商品。利润最高商品按未四舍五入的单件利润比较；并列时全部显示。若全部商品亏损，仍显示其中亏损最少者，并明确说明。
- 商品名称为必填，最多 100 字符；成本和运费在 0–10 亿元之间，售价大于 0 且不超过 10 亿元；平台费率 0–100%。金额和费率均最多两位小数，不接受负数、科学计数法、NaN、Infinity 或超范围数值。非法输入保留以便更正，结果显示「—」，不会用零冒充结果。
- 费率 100% 且成本或运费大于零时，显示「无法保本」；成本和运费均为零时，显示「任意正售价均保本」，不做除零运算。
- 计算使用整数分与费率基点保留中间精度，显示/CSV 保留两位小数。总利润汇总未四舍五入的数值，所以与逐项显示值相加可能有尾差。
- 全部行有效后可导出 CSV，包含输入字段、计算结果、盈亏状态和总利润行；使用 UTF-8 BOM、CRLF 和 CSV 引号转义，兼容常见表格软件。名称若以公式前缀开头，导出时增加单引号，避免表格软件将名称当作公式执行。CSV 是结果报告，当前不提供 CSV 回导功能。
- 草稿（含待完善行）自动保存在独立键 `linggan-batch-profit-v1`，刷新后恢复。输入仅在当前浏览器处理，不上传。存储被禁用、配额不足或数据损坏时会明确提示仅本次页面有效，仍可计算和导出有效数据；损坏的原始数据不会自动覆盖，可确认清空后重新保存。
- 用户中心的「清除平台本地数据」仍是全平台清除，会连同批量分析数据一起删除，确认文案已明确列出范围。清理浏览器数据同样会丢失草稿，建议导出 CSV 留存。

### 商品利润分析历史记录（第二阶段）

1. 在批量分析器填写全部商品，确认每行输入有效，然后点击「保存本次分析」。每次点击会保存一份独立快照，不修改当前草稿和 CSV 功能。
2. 从侧边导航或分析器的「查看历史记录」进入 `#history`，查看保存日期（北京时间 UTC+8）、商品数量、总利润和商品名称概览。
3. 点击「查看详情」查看全部商品输入、利润、利润率、平台费用与保本售价。已保存的快照不会跟随当前草稿的编辑而改变。
4. 点击「恢复到分析器」或详情中的恢复按钮。当前存在草稿时会要求确认替换；恢复成功后立即自动保存草稿，历史快照本身保持不变。恢复后仍可继续编辑和导出原有 CSV。
5. 单条删除和清空全部历史记录都需要确认。历史页的清空只影响分析历史，不改变草稿、提示词、收藏或个人资料。用户中心「清除平台本地数据」则明确包含全部分析历史。

存储键为 `linggan-profit-history-v1:<项目路径>`，例如 `linggan-profit-history-v1:/codex-project`。`/codex-project/` 和 `/codex-project/index.html` 使用同一个键；不同项目路径的**新增历史记录**互相隔离。该隔离仅适用于新增历史键，已有工作空间和草稿键保持兼容，不在本次变更中迁移。

存储结构为 `{version:1, records:[{id, createdAt, productCount, totalProfit, rows}]}`。日期保存为 UTC ISO 字符串，页面以北京时间显示；`rows` 包含商品名称、成本、售价、运费和费率的输入快照，查看时按现有公式计算明细。总利润仍按每种商品各一件汇总。读取时校验版本、唯一 ID、日期、行数、金额输入及数量/总利润的一致性，不接受损坏或被篡改的记录。

最多保留 100 条，每条最多 200 款商品。达到上限时要求用户先删除旧记录，不会自动淘汰历史。浏览器配额可能在达到条数上限前耗尽；保存/删除失败时明确提示，不产生“已成功保存”的假记录，不静默覆盖损坏数据。读取或 JSON 解析异常时可重新检查权限，或确认清空历史数据后重新开始。恢复时若草稿无法持久保存，则保持当前草稿不变。所有数据保存在当前浏览器，无登录、云数据库、付费 API 或额外服务器。

同一项目的其他标签页发生历史变更时，列表通过 `storage` 事件刷新；保存/删除前重新读取最新数据，减少旧列表覆盖风险。localStorage 不提供跨标签页事务，极短时间内同时操作仍可能发生最后写入覆盖；请避免多个标签页同时保存或删除。所有用户文本通过 `textContent` / 表单值显示，不作为 HTML 解析。清理浏览器数据会删除历史，CSV 可作为报告留存，当前不提供历史 JSON/CSV 回导。

### 本地数据与隐私

提示词、收藏、用户资料存储在当前站点的 `localStorage`，键为 `linggan-workspace-v1`。不同浏览器、设备、域名或隐私会话之间不会自动同步。GitHub Pages 同一域名下的其他项目可共享存储作用域，不要存放密钥或敏感资料。

默认没有任何 AI 网络请求；输入内容不会上传。页面仅引用本站静态资源，无外部字体/CDN。用户输入通过 `textContent` / 表单值渲染。剪贴板需要浏览器许可和安全上下文；不可用时提示手动复制。存储不可用、已满或原始数据损坏时显示警告，仍可处理文本、计算和导出当前数据，不会伪称保存成功。原始损坏数据不会被自动覆盖。

提示词最多 200 条，每条名称 100 字符、正文 20,000 字符；文本输入最多 200,000 个 UTF-16 字符。导入为合并操作，不覆盖已有提示词，相同名称/分类/内容的条目跳过。请定期导出备份，清理浏览器数据将删除本地记录。文本和单品利润计算输入只保留在当前页面内存中；批量商品分析按上述独立键保存草稿。

## 运行与访问

直接打开 `index.html` 即可使用本地功能。也可在项目目录启动服务器：

```bash
python3 -m http.server 8000
```

如果服务器运行在自己的电脑，可在同一台电脑访问 `http://localhost:8000`。如果服务器运行在 Codex 云端，Windows 的 localhost 无法访问它，必须使用平台实际提供的转发/预览入口或 GitHub Pages；启动服务器不会自动创建公网网址。

GitHub Pages 配置保持 **Deploy from a branch → main → / (root)**。`.nojekyll` 已保留。启用 Pages 且部署成功后的默认网址：

## AI 后端接口预留

`script.js` 中的 `window.LingganAI.generate(request, { signal })` 提供 POST/JSON 响应适配器，默认 `endpoint: ''`，调用时明确抛出“尚未接入 AI API”。两个生成按钮保持禁用；本地整理提示词和下载请求不会调用该适配器。

导出的请求示例：

```json
{
  "tool": "article",
  "messages": [{ "role": "user", "content": "用户整理的提示词" }],
  "parameters": {
    "topic": "文章主题",
    "audience": "目标读者",
    "tone": "专业清晰",
    "length": "1000",
    "keywords": "补充要求"
  }
}
```

标题工具的 `tool` 为 `title`，参数为 `product`、`sellingPoints`、`platform`、`count`、`keywords`、`maxLength`。表单参数当前以字符串导出，后端应校验类型、范围、长度并做转换。成功响应约定为 `{ "text": "真实模型输出" }`；适配器处理非成功 HTTP 状态和无效响应结构。

未来接入时，在源码配置可信 HTTPS 后端 endpoint，增加认证/限流/超时/错误处理与加载状态，再连接按钮调用适配器；跨域后端需允许实际 Pages 来源的 CORS 请求。**API 密钥必须留在后端，不要写入 HTML、JavaScript、GitHub 仓库或浏览器存储。** GitHub Pages 不能运行后端，也不能安全保管模型密钥。
